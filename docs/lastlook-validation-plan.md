# LastLook 可验证指标与测试方案

## 1. 验证目标

LastLook 的验证重点不是证明它已经可以覆盖所有厨房风险，而是证明首版 MVP 是否能稳定完成一个明确任务：

用户离家后，系统能否在可接受时间内给出一张可信的灶台确认卡片。

## 2. 核心指标

| 指标 | 定义 | 目标值 | 测量方式 |
| --- | --- | --- | --- |
| 确认耗时 | 从点击开始检查到结果卡片出现的时间 | Demo 阶段 30 秒内 | 前端计时或后台 `createdAt` 到 `completedAt` |
| 场景完成率 | 三种 Demo 场景是否能稳定跑完 | 100% | 已确认、无法确认、异常各跑 3 次 |
| 无法确认率 | 遮挡、过暗、模糊等情况下返回无法确认的比例 | 不追求越低越好，先要求原因准确 | 用遮挡和暗光样本测试 |
| 异常识别准确性 | 旋钮明显偏离基准时是否返回异常 | 小样本中达到可演示稳定性 | 使用预设异常样本验证 |
| 用户信任 | 用户是否愿意查看证据照片并接受结论 | 访谈中多数人认为有帮助 | 5 到 8 人小样本访谈 |

## 3. Demo 阶段测试方案

### 3.1 自动测试

执行：

```bash
npm test
```

覆盖内容：

- 服务健康检查。
- 设备状态接口。
- 三种场景切换。
- 检查启动。
- 检查结果读取。
- 结果状态和证据字段校验。

### 3.2 手动测试

测试地址：

```text
https://13-57-166-217.sslip.io/lastlook/
```

测试步骤：

1. 打开线上 Demo。
2. 选择“已确认”，点击“开始出门检查”。
3. 确认结果卡片显示“灶台已确认关闭”。
4. 选择“无法确认”，重复检查流程。
5. 确认结果卡片显示“暂时无法确认灶台状态”。
6. 选择“异常”，重复检查流程。
7. 确认结果卡片显示“疑似有旋钮未关闭”。
8. 检查当前照片、全关基准照片和判断依据是否完整。

通过标准：

- 三种场景都能完成。
- 页面无空白、错位或按钮失效。
- 结果文案和证据照片一致。

## 4. 真实设备小样本测试

真实 eufy SDK 接入后，使用一个固定厨房或模拟厨房台面进行测试。

### 4.1 样本设置

| 样本 | 设置方式 | 预期结果 |
| --- | --- | --- |
| 全关状态 | 所有旋钮处于关闭位置 | 已确认 |
| 遮挡状态 | 锅具挡住一个或多个旋钮 | 无法确认 |
| 暗光状态 | 关闭主要光源，启用夜视或补光 | 已确认或无法确认 |
| 异常状态 | 一个旋钮偏离全关位置 | 异常 |

### 4.2 记录字段

- 测试时间。
- 光线情况。
- 是否有遮挡。
- 摄像头是否在线。
- 检查耗时。
- 输出结果。
- 输出原因。
- 用户是否认可结果。

## 5. 用户访谈问题

每位用户看完 Demo 后回答以下问题：

1. 你是否遇到过出门后担心灶台、门锁或电器没关的情况？
2. 看到证据照片后，你是否比只看到文字提醒更放心？
3. 如果系统提示“无法确认”，你是否觉得这个结果可信？
4. 你是否接受摄像头只在检查时转向灶台？
5. 你是否愿意把这个能力作为购买室内摄像头的理由之一？

记录方式：

- 每题记录一句原话。
- 标记正向、中性或负向。
- 不把访谈结果包装成大规模市场结论。

## 6. 提交材料中的表达边界

可以表达：

- 当前 Demo 已经跑通完整流程。
- 三种结果可以稳定演示。
- 技术路线可替换为真实 eufy SDK。
- 下一步将验证真实设备耗时、无法确认率和用户信任。

不表达：

- 已经接入真实 eufy SDK。
- 已经证明可以避免厨房事故。
- 已经达到某个真实准确率。
- 可以远程关火。
- 可以持续监控家庭安全。

## 7. 当前结论

LastLook 当前阶段已经满足预赛 Demo 的基本验证要求：

- 有线上可访问 Demo。
- 有前端和后台闭环。
- 有三种可演示结果。
- 有明确技术替换点。
- 有下一阶段真实设备验证方案。
