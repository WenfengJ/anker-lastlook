# LastLook 精细化任务指令

## 使用方式

本文件用于把 `docs/lastlook-todolist.md` 中的待完成事项拆成可逐条执行的任务指令。每次只执行一条任务，完成后再进入下一条。

每条任务都要求：

- 只围绕 LastLook 当前 MVP：出门后确认灶台是否关闭。
- 不扩展成完整智能家居平台。
- 不写空泛愿景。
- 产出必须能用于参赛材料、原型、Demo、工程开发或校稿。
- 完成后更新 `docs/lastlook-todolist.md` 中对应状态。

## 0. 产品澄清问题

任务指令：

```text
请基于当前 LastLook 背景，从产品经理角度提出一组必须确认的问题，用来锁定 MVP 范围。

要求：
- 问题数量控制在 12 个以内。
- 按优先级分组：必须回答、可以默认、暂不处理。
- 每个问题都说明它会影响哪个交付物，例如 PRD、原型、技术架构、Demo。
- 不要问泛泛的商业愿景问题，只问会影响当前 MVP 的具体问题。
- 最后给出你建议的默认答案，方便我不回答时也能继续推进。
```

验收标准：

- 问题能帮助收窄功能，而不是打开更多方向。
- 默认答案可以直接进入 MVP PRD。

## 1. MVP PRD

任务指令：

```text
请按照 `docs/lastlook-todolist.md` 的第 1 项，完成 LastLook MVP PRD。

输入背景：
- LastLook 是一个由 eufy 摄像头驱动的出门安全确认清单。
- 首版只聚焦：用户出门后确认灶台是否关闭。
- 核心闭环：离家触发、摄像头转向灶台、拍照、基准图比对、补光复查、生成结果卡片。

输出要求：
- 新建或更新 `docs/lastlook-mvp-prd.md`。
- 内容包含：产品一句话定义、目标用户、核心场景、MVP 范围、非 MVP 范围、用户流程、功能需求、异常状态、隐私要求、验收标准。
- 用简洁产品文档语言，不写宣传文案。
- 所有需求必须能服务 90 秒 Demo 和原型图。

校稿要求：
- 删除不服务“灶台确认”的功能。
- 标出任何仍不确定但可以默认的假设。
- 完成后更新 `docs/lastlook-todolist.md` 中 MVP PRD 状态。
```

验收标准：

- 可直接指导原型图、技术架构和 Demo 脚本。
- 没有扩展成宠物、老人看护、完整安防平台。

## 2. 90 秒 Demo 脚本

任务指令：

```text
请按照 `docs/lastlook-todolist.md` 的第 2 项，完成 LastLook 90 秒 Demo 脚本。

输出要求：
- 新建或更新 `docs/lastlook-demo-script.md`。
- Demo 必须围绕一个主故事：用户出门后担心灶台没关。
- 按时间轴写，建议每 10 到 20 秒一个动作。
- 包含：开场痛点、离家触发、摄像头转向灶台、拍照比对、补光复查、结果卡片、用户决策、结尾价值。
- 同时写出演示画面、旁白、系统动作。

边界：
- 不写长篇演讲稿。
- 不加入复杂商业模式。
- 不要求真实硬件全部接通，可以允许模拟事件，但要标明哪些是真实、哪些是模拟。

校稿要求：
- 90 秒内能讲完。
- 每一步都能在原型或视频里呈现。
- 完成后更新 `docs/lastlook-todolist.md` 中 Demo 脚本状态。
```

验收标准：

- 评委能在 90 秒内理解产品。
- 后续原型图能逐帧对应 Demo。


## 6. 可验证指标与测试方案

任务指令：

```text

- 指标至少包含：确认耗时、无法确认率、异常识别准确性、用户信任。

边界：
- 不写大规模商业化 A/B 测试。
- 不承诺医疗或心理疗效。

校稿要求：
- 每个指标都能用现场 Demo 或小样本验证。
- 指标服务“可演示、可验证”的参赛要求。
- 完成后更新 `docs/lastlook-todolist.md` 中可验证指标与测试方案状态。
```

验收标准：

- 可以回答评委“你怎么证明它有用”。
- 指标不夸张，且能在短时间内收集证据。
