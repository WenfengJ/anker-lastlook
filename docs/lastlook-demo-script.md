## 90 秒版本

大家好，这是 LastLook。

它解决的是一个很具体的问题：出门之后，突然怀疑灶台到底关了没有。

这件事不一定是忘了，而是不确定。用户真正需要的不是一句提醒，而是一张来自家里的证据照片。

LastLook 把 eufy 室内云台摄像头变成一个出门安全确认工具。第一次使用时，用户把摄像头转到灶台，保存一张“全关”基准照片。之后每次出门，系统自动触发检查。

现在看 Demo。

我点击“开始出门检查”。摄像头转到灶台预设位，拍摄当前照片，和基准照片做比对。这里用的是 eufy 摄像头已有能力：PTZ 预设位、拍照、补光/夜视和隐私区。

结果只会有三种。

第一种，已确认。旋钮位置和基准照片一致，用户看到“灶台已确认关闭”，并且能点开当前照片和基准照片。

第二种，无法确认。比如锅挡住了旋钮，系统不会假装看懂，而是直接告诉用户无法确认，并给出照片证据。

第三种，异常。当前照片和基准照片不一致，用户会看到“疑似有旋钮未关闭”，再决定是否返回处理。

LastLook 的价值不是让摄像头多录一段视频，而是让它在用户离家后完成一次可信确认。它先从灶台开始，之后可以扩展到卷发棒、门锁、燃气报警器和更多出门检查点。

我们已经完成了本地前端和后台 Demo，三种场景都可以稳定演示。下一步会验证确认耗时、无法确认率，以及用户是否愿意持续查看这张确认卡片。

## 60 秒压缩版

LastLook 解决一个很具体的问题：出门后怀疑灶台到底关了没有。

用户需要的不是普通提醒，而是一张可信证据。第一次使用时，用户保存一张灶台“全关”基准照片。之后离家时，eufy 摄像头转到灶台预设位，拍摄当前照片，并和基准照片比对。

结果只有三种：已确认、无法确认、异常。

已确认时，用户看到灶台关闭和证据照片。无法确认时，比如锅挡住旋钮，系统不会假装确定。异常时，用户看到当前照片与基准照片不一致，再决定是否返回处理。

这用到了 eufy 摄像头的 PTZ 预设位、拍照、补光/夜视和隐私区。LastLook 不是完整智能家居平台，首版只打穿灶台确认闭环。

我们已经完成本地前端和后台 Demo，三种场景都能稳定演示。下一步会验证确认耗时、无法确认率和用户持续使用意愿。

## Demo 操作词

### 操作 1：打开首页

讲解：

这里是 LastLook 首页。用户出门前不需要打开完整监控，只需要点击“开始出门检查”。

### 操作 2：点击开始检查

讲解：

系统开始执行检查。摄像头转到灶台预设位，拍摄当前照片，并与基准照片比对。

### 操作 3：展示已确认

讲解：

这是正常结果。用户看到灶台已确认关闭，也能查看当前照片和全关基准照片。

### 操作 4：切换无法确认

讲解：

如果锅或阴影挡住旋钮，系统会直接提示无法确认。这里的重点是可信，不确定时不输出肯定结论。

### 操作 5：切换异常

讲解：

如果当前照片和基准照片不一致，系统提示疑似有旋钮未关闭。用户可以查看证据后决定是否返回处理。

## 评委问答准备

### 为什么不直接做烟雾报警？

烟雾报警通常发生在风险已经出现之后。LastLook 解决的是离家后的最后一次确认，尽量在事前发现不确定和异常。

### 为什么不用通用物体识别？

首版不依赖通用识别。固定机位、固定灶台、固定旋钮区域，再和用户自己的基准照片比对，更稳定，也更容易解释。

### 为什么会有“无法确认”？

安防产品不能假装确定。遮挡、过暗或画面不清时，系统直接告诉用户无法确认，并展示证据照片。

### 当前 Demo 是否接入真实 eufy SDK？

当前 Demo 使用本地前端、后台和设备模拟器，稳定展示产品闭环。真实接入时替换摄像头控制、拍照和设备状态接口，不改变用户流程。

### 用户会不会觉得被监控？

LastLook 只在出门检查时转向灶台，并强调隐私区和检查点照片。它不持续观看生活画面，只确认用户指定的安全点。
