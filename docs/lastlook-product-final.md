# LastLook 产品定稿

## 1. 产品一句话

LastLook 让 eufy 摄像头在用户出门后自动检查灶台，用一张带证据的照片告诉用户是否可以放心离开。

## 2. 核心问题

用户离家后经常会突然怀疑灶台是否已经关闭。反复回忆和反复检查会增加不确定感，真正需要的是一次来自外部、可查看证据的确认。

LastLook 只解决一个问题：

灶台现在是否处于用户设定的“全关”状态。

## 3. 目标用户

### 3.1 首要用户

经常在出门后担心灶台、炉具或厨房设备没有关闭的家庭用户。

典型特征：

- 早上出门节奏快。
- 做饭后容易反复确认。
- 已有或愿意购买室内云台摄像头。
- 需要证据照片，而不是一句没有依据的提醒。

### 3.2 次要用户

为父母或独居家人配置家庭安全设备的成年子女。

典型特征：

- 希望降低厨房风险。
- 不希望把家变成持续监控场景。
- 更容易接受“只确认安全点”的轻量方案。

## 4. MVP 范围

首版只做“出门后确认灶台是否关闭”。

### 4.1 必须包含

- 设置灶台“全关”基准照片。
- 保存灶台摄像头预设位。
- 用户手动触发或模拟离家触发检查。
- 展示检查中流程。
- 展示三种结果：
  - 已确认
  - 无法确认
  - 异常
- 每个结果都展示当前照片和基准照片。
- 光线不足或遮挡时进入“无法确认”逻辑。
- 展示隐私说明：只在检查时转向灶台，不持续查看生活画面。

### 4.2 可以作为演示模拟

- 离家或锁门事件。
- 摄像头转向灶台预设位。
- 补光/夜视复查。
- 图像比对结果。
- 三种检查结果场景切换。

### 4.3 不做

- 不做完整智能家居平台。
- 不做宠物、门卫、老人看护等其他场景。
- 不做真实远程关火。
- 不做保险后台。
- 不做多房间、多摄像头、多家庭管理。
- 不做复杂账号体系。
- 不把卷发棒、门锁、燃气报警器纳入首版主闭环。

## 5. 用户流程

### 5.1 首次设置

1. 用户打开 LastLook。
2. 选择灶台作为检查点。
3. 摄像头转到灶台视角。
4. 用户确认所有旋钮处于关闭状态。
5. 系统保存“全关”基准照片。
6. 系统保存灶台预设位。
7. 用户看到设置完成状态。

### 5.2 出门检查

1. 用户离家，或点击“开始出门检查”。
2. 系统展示检查中状态。
3. 摄像头转到灶台预设位。
4. 系统拍摄当前照片。
5. 系统比对当前照片和基准照片。
6. 系统生成结果卡片。
7. 用户查看结论和证据照片。

### 5.3 用户处理

已确认：

- 用户看到“灶台已确认关闭”。
- 用户可点开当前照片和基准照片。
- 用户点击“我知道了”结束流程。

无法确认：

- 用户看到“无法确认灶台状态”。
- 系统说明原因，例如遮挡、过暗或画面不清。
- 用户查看照片后决定是否回家或稍后复查。

异常：

- 用户看到“疑似未关闭”。
- 系统展示异常说明和证据照片。
- 用户查看照片并标记已处理。

## 6. 页面清单

### 6.1 首页 / 今日确认状态

作用：

- 展示最近一次检查状态。
- 提供开始检查入口。
- 展示摄像头和隐私状态。

核心元素：

- 产品名 LastLook。
- 最近一次检查结果。
- “开始出门检查”按钮。
- 摄像头在线状态。
- 隐私区状态。

### 6.2 检查中页面

作用：

- 让用户看到系统正在执行检查。

核心元素：

- 当前步骤。
- 检查进度。
- 预计完成时间。
- 灶台预设位、拍照、比对等步骤说明。

### 6.3 检查结果页

作用：

- 展示检查结论和证据。

核心元素：

- 结果状态。
- 一句话结论。
- 当前照片。
- 基准照片。
- 判断依据。
- 用户操作按钮。

### 6.4 灶台基准设置页

作用：

- 设置或更新“全关”基准照片。

核心元素：

- 当前基准照片。
- 摄像头预设位状态。
- “更新基准照片”按钮。
- 旋钮区域说明。

### 6.5 隐私与摄像头设置页

作用：

- 说明系统何时查看灶台、如何保护隐私。

核心元素：

- 只在离家检查时转向灶台。
- 隐私区已设置。
- 本地优先处理说明。
- 无法确认时直接提示，不假装确定。

## 7. 功能需求

### 7.1 基准照片

- 用户可以设置一张“全关”基准照片。
- 基准照片必须绑定灶台预设位。
- 页面需要展示基准照片创建时间。
- 用户可以更新基准照片。

### 7.2 检查触发

- MVP 支持手动点击“开始出门检查”。
- Demo 中可模拟离家触发。
- 触发后进入检查中页面。

### 7.3 检查过程

- 系统展示检查步骤。
- 步骤至少包含：
  - 检测离家状态。
  - 转到灶台预设位。
  - 拍摄当前照片。
  - 对比基准照片。
  - 生成结果。

### 7.4 检查结果

结果只能是三类：

- 已确认：当前照片与基准状态一致。
- 无法确认：画面遮挡、过暗、模糊或缺少基准照片。
- 异常：当前状态明显偏离基准照片。

每个结果必须包含：

- 状态标签。
- 一句话结论。
- 判断依据。
- 当前照片。
- 基准照片。
- 用户下一步操作。

### 7.5 Demo 场景切换

- 开发和演示环境需要支持三种场景切换：
  - 已确认
  - 无法确认
  - 异常
- 场景切换只用于演示和测试。
- 正式材料中需说明哪些能力为演示模拟。

## 8. 状态文案

### 8.1 已确认

主文案：

灶台已确认关闭。

辅助文案：

旋钮位置与基准照片一致。可以放心出门。

### 8.2 无法确认

主文案：

暂时无法确认灶台状态。

辅助文案：

旋钮区域被遮挡或画面不清。请查看照片后决定是否复查。

### 8.3 异常

主文案：

疑似有旋钮未关闭。

辅助文案：

当前照片与基准照片不一致。请查看证据照片并处理。

## 9. 隐私要求

- 只在用户触发或离家触发时检查灶台。
- 默认展示检查点照片，不展示无关生活区域。
- 支持隐私区说明。
- 不确定时输出“无法确认”，不输出虚假的肯定结论。
- 演示版本不保存真实家庭敏感画面。

## 10. 验收标准

产品定稿满足以下标准即可进入原型和开发：

- 场景只聚焦灶台关闭确认。
- 用户流程可以在 90 秒内演示。
- 三种结果状态清楚。
- 每种结果都有证据照片入口。
- 前端页面数量控制在 5 个以内。
- 后台可以用模拟数据支撑完整流程。
- 不依赖真实 eufy SDK 才能完成演示。

## 11. 下一步

进入第 2 步：LastLook 原型方案。

原型需要基于本产品定稿，优先完成以下四个画面：

1. 出门后自动检查中。
2. 灶台已确认关闭。
3. 无法确认，锅挡住旋钮。
4. 异常，疑似未关闭。
